# ADR 0010：本地控制面使用 SQLite 持久化

## 状态

已接受，作为本地 MVP 和未来 PostgreSQL 适配器的参考实现。

## 背景

此前的蓝图、知识和执行状态主要存在内存中，页面刷新或服务重启后无法形成产品闭环。阶段 9 需要先建立清晰的数据边界，再考虑生产数据库与分布式部署。

## 决策

1. 新增独立 `ControlPlaneStore`，API 和业务模块不直接散落 SQL。
2. 蓝图当前状态与不可变版本分表保存，版本通过内容哈希追踪。
3. 知识文档、评测记录和发布记录全部带 `tenant_id`，所有查询强制使用租户过滤。
4. 发布动作只相信服务端保存的最新评测结果；当前版本没有通过评测时返回冲突并拒绝发布。
5. 本地环境采用 Python 标准库 SQLite，避免为了原型过早引入大型 ORM；生产阶段通过相同仓储边界替换为 PostgreSQL。
6. 数据库文件进入 `data/`，由 Git 忽略，不与源码或密钥一起提交。

## 结果

本地系统现在具备保存蓝图、查看版本、维护知识、保存评测、执行发布门禁和记录生产发布的完整控制面闭环。
