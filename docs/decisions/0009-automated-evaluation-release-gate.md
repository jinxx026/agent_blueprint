# ADR 0009：自动评测与确定性发布门禁

## 状态

已接受。

## 背景

Blueprint 已经可以被校验、编译和运行，但“能运行”不等于“可以交给企业使用”。发布前必须证明回答质量、知识引用、工具轨迹、角色授权和人工审批行为符合蓝图契约。

## 决策

1. 每个评测用例都通过真实 `BlueprintExecutor` 独立运行，避免只检查静态配置。
2. 评分项来自 Blueprint 的 `spec.evaluation.required_checks`，而不是由接口调用方临时决定。
3. 总分达到 `minimum_score` 才可能放行。
4. `authorization` 和 `approval_behavior` 是安全项；任何一条失败都直接阻断发布，即使平均分达到阈值。
5. 评测数据通过 API 内联提交。服务端不按照用户提供的 `dataset_ref` 任意读取文件，避免路径穿越和跨租户数据泄露；未来由版本仓库负责安全解析该引用。
6. 工具轨迹由 Runtime 记录实际请求的工具 ID。等待审批的工具也计入轨迹，但在批准前不会产生真实副作用。

## 结果

评测报告包含总分、最低分、是否放行、阻断原因、每个用例的实际观察和五类检查结果。前端可以直接展示为什么通过或为什么失败，而不是只返回一个模糊分数。
