# AgentBlueprint 产品需求文档

状态：Accepted  
目标版本：v1.0  
最后更新：2026-09-02

## 1. 问题定义

企业希望把大模型用于内部知识查询和业务执行，但通常缺少智能体工程能力。现有搭建方式容易把岗位目标、业务规则、Prompt、权限和工具配置混在一起，导致以下问题：

- 业务人员难以准确描述技术配置。
- Prompt 难以审查、复用和版本管理。
- 智能体可能越权调用工具或绕过审批。
- 模型、知识或规则更新后缺少回归测试。
- 从原型进入测试和生产环境时需要重复配置。

AgentBlueprint 将企业业务要求表达为结构化蓝图，再把蓝图编译为可执行、可测试的智能体配置。

## 2. 目标用户

### 2.1 业务负责人

定义智能体岗位、操作规则和成功标准，但不需要理解 Prompt 或模型参数。

### 2.2 AI 应用开发者

维护连接器、运行时和行业模板，需要稳定、可版本化的配置接口。

### 2.3 企业管理员

管理用户、数据权限、工具授权、发布审批和审计记录。

### 2.4 评测与合规人员

建立验收集，检查回答、工具轨迹、权限和高风险操作是否符合要求。

## 3. 核心用户故事

1. 作为业务负责人，我可以通过向导描述一个岗位，而不必手写系统 Prompt。
2. 作为开发者，我可以用 YAML/JSON 管理相同的 Blueprint，并纳入 Git 版本控制。
3. 作为管理员，我可以限定某个角色能使用哪些知识和工具。
4. 作为审批人，我可以在高风险操作执行前查看依据并批准或拒绝。
5. 作为评测人员，我可以用历史案例验证新版本是否出现退化。
6. 作为运维人员，我可以追踪一次运行中的模型、知识、工具和审批事件。

## 4. v1 产品范围

### 4.1 Blueprint 管理

- 网页向导创建和编辑 Blueprint。
- 提供 Blueprint 规范范围内的受约束流程画布，支持 Agent、RAG、条件、工具、审批与输出节点。
- 业务向导、流程画布和 YAML/JSON 必须双向映射到同一个 Blueprint 数据模型。
- YAML/JSON 导入、导出与版本管理。
- JSON Schema 和跨字段业务校验。
- 草稿、测试、生产三个生命周期阶段。

### 4.2 编译与运行

- Blueprint 编译为模型无关的执行计划。
- 支持单智能体、多轮工具调用和明确停止条件。
- 使用 LangChain 提供模型、工具、Retriever 与单 Agent 抽象。
- 使用 LangGraph 支持 Supervisor、Router、Handoff 和自定义多 Agent 图。
- 支持持久状态、并行委派和 human-in-the-loop 审批恢复。
- 支持模型适配器，第一版至少接入一个真实模型和一个测试模型。
- 支持超时、最大步骤、成本预算和失败策略。

### 4.3 知识与工具

- 支持 PDF、DOCX、TXT 知识文件。
- 支持 two-step、agentic 和 hybrid 三类 RAG 策略。
- 回答提供知识来源、文档版本和片段定位。
- 支持只读数据库查询、REST/OpenAPI 和 MCP 工具。
- 工具具有风险等级、参数结构和角色权限。

### 4.4 治理

- 组织级数据隔离和角色权限。
- 高风险工具人工审批。
- 执行轨迹和不可静默修改的审计事件。
- Prompt 注入、敏感数据和越权调用的基础防护。

### 4.5 评测

- Blueprint 绑定评测数据集和最低发布分数。
- 支持最终答案、引用、工具选择、参数、审批和拒绝行为评测。
- 支持版本回归对比。
- 评测失败阻止版本进入生产。

### 4.6 交付

- 提供 Docker Compose 私有部署方式。
- 提供知识助手、售后客服、采购审核三个完整模板。
- 提供 API 文档、运维文档和架构说明。

## 5. v1 非目标

以下内容不进入 v1，以避免项目失去核心边界：

- 无限自由的通用低代码编排器、任意代码节点和无治理的插件市场。
- 任意数量智能体之间的自由协作。
- 模型训练或微调平台。
- 百种第三方 SaaS 连接器市场。
- Kubernetes 自动运维平台。
- 自主付款、删除生产数据等不可逆高风险操作。

## 6. 第一个参考场景

客服退款助理用于验证整个产品闭环：

1. 客服提交客户问题和订单号。
2. 智能体查询售后政策和订单信息。
3. 确认身份、订单状态和退款金额。
4. 生成处理建议；必要时请求主管审批。
5. 经批准后调用退款草稿工具。
6. 保存引用、工具调用、审批与最终结果。

该场景同时覆盖知识检索、只读工具、写工具、金额规则、身份校验、人工审批和评测。

## 7. 功能验收指标

- 新用户能在 15 分钟内完成一个模板智能体配置。
- 同一 Blueprint 可以在测试模型和真实模型之间切换而不修改业务字段。
- 每次知识型回答都能返回来源和内容版本。
- 未授权用户的工具调用阻止率为 100%。
- 标记为需要审批的工具在批准前执行次数为 0。
- 每次运行都生成按时间排序的执行事件。
- 新版本未达到 Blueprint 最低评测分数时无法发布。
- 三个示例智能体均由同一编译器和 Runtime 执行。
- Docker Compose 能在一台开发机上启动完整系统。

## 8. 非功能指标

- 普通非流式 API 请求的框架额外开销目标低于 300 ms，不包含模型和外部系统耗时。
- 服务重启后，等待审批和长任务状态可以恢复。
- 密钥不进入 Blueprint、日志、Git 或模型上下文。
- 所有数据库记录包含组织标识，敏感查询强制进行租户过滤。
- 核心模块具有自动化单元测试；关键业务流程具有集成测试。

## 9. 成功标准

项目达到 v1 不以代码量为标准，而以闭环为标准：三种不同业务模板能够被配置、编译、评测、发布和运行，并由至少一个外部真实用户完成试用和反馈。

## 10. 主要风险

- 范围膨胀：通过版本非目标和模板数量限制控制。
- 模型不稳定：通过确定性规则、结构化输出和回归评测控制。
- 数据越权：通过组织隔离、角色权限和工具执行前检查控制。
- 外部工具产生副作用：通过风险分级、幂等键和审批控制。
- 文档检索结果失真：通过引用、版本记录和检索评测控制。
